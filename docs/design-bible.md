# 서론: 이 문서의 위상과 용법

이 문서는 「무제(無題)」의 **유일한 설계 진실 원천(Single Source of Truth)**이다. 기술 아키텍처 청사진(`detective-game-blueprint.md`)이 "어떻게 만드는가"를 규정한다면, 이 문서는 "왜 이렇게 만드는가, 무엇이 재미이고, 무엇이 금지인가"를 규정한다.

모든 기능 추가, 콘텐츠 작성, UI 변경, 테스트 기준은 이 문서에서 도출되어야 한다. 이 문서에 근거 없는 기능은 허용되지 않는다.

**사용법**: 엔진 개발자는 제4~6장+제9장, UI 개발자는 제3장+제12장, 시나리오 작가는 제4장+제9~10장, QA는 제9.2장+부록 B를, 전체 팀은 제13~15장을 바이블로 삼는다.

# 제1장. 게임의 정체

## 1.1 한 문장 정의

**절차적으로 생성된 사건을, 탐정이 되어 현장 조사와 용의자 탐문을 통해 해결하는 단편 추리 게임.**

## 1.2 핵심 경험: 플레이어는 15~20분 안에 이것을 체험한다

1. 사건 현장에 도착하여 물리적 증거를 발견한다
2. 용의자들의 증언을 듣고, 그 속의 모순을 포착한다
3. 처음에 잘못된 사람을 의심한다 — 그리고 그 확신이 무너진다
4. 진범을 특정하고, 증거를 들어 고발한다
5. 사건의 전모가 드러나며, 모든 증거가 새로운 의미로 재해석된다

## 1.3 세 가지 쾌감

이 게임이 존재하는 이유. MVP가 검증해야 하는 것은 정확히 이 세 쾌감의 발생 여부이다.

**쾌감 1: "아, 그 사람이었구나" — 오판 후 재구성**
오판 곡선의 ③(붕괴 증거)을 발견하는 순간, 지금까지의 모든 증거가 새로운 의미로 재배열되는 경험.

**쾌감 2: "잡았다" — 짚기의 손맛**
탐문에서 용의자의 증언 속 모순을 포착하는 순간. 이 질문을 던지는 순간의 전율. 분류보다 타격감이 먼저.

**쾌감 3: "증명했다" — 고발의 비가역적 결단**
증거를 모으고, 모순을 짚고, 재구성한 뒤, 최종적으로 "이 사람이 범인이다"라고 선언하는 순간. 돌이킬 수 없다는 것이 이 순간의 무게를 만든다.

## 1.4 구조 전환의 기록: 용의자 → 탐정

### 폐기한 것: 용의자-루프 구조

원래 설계에서 플레이어는 용의자(에이든 화이트)가 되어 타임리프를 반복하며 자기 혐의를 벗기는 구조였다. 다음을 폐기한다.

- **타임리프**: 3분 타이머 + 루프 반복. 시간 역행 메커니즘.
- **흔적 관리**: 지문을 남기지 않으려는 자기방어. "보기만 하기/만져서 조사/가져가기"의 3단계.
- **혐의 시스템**: 0~100 혐의 수치. 100이면 체포.
- **루프 간 기억 열화**: 선택지 텍스트 누락, NPC 위치 미세 변동.
- **롤랜드의 심문**: 탐정(피에르 롤랜드)이 질문하고 플레이어가 방어하는 수동적 구조.
- **"화이트가 범인인가?"라는 존재론적 불안**.

### 강화하는 것: 탐정 구조

용의자-루프의 절반은 폐기하고 절반은 더 강해진다.

- **오판 곡선**: 그대로 유지. 탐정이 "틀리는 경험"이야말로 추리의 쾌감.
- **증거의 2해석**: 그대로 유지. 교차 검증으로만 해석 확정.
- **짚기의 손맛**: 수동 방어에서 능동 공격으로 전환. 플레이어가 모순을 짚는다.
- **고발의 비가역성**: Qud의 퍼마데스에 대응. 한 번 고발하면 끝.
- **수첩(조서)의 진행 보상**: 매 스텝마다 수첩이 채워지는 것 자체가 진행감.

### 전환의 핵심 이유

탐정이 되면 **"왜 이 사람이 범인인가?"를 증명하는 쾌감**이 게임의 중심에 온다.

# 제2장. 이론적 기반: 세 축의 교차

이 장은 설계의 지적 근거를 기록한다. **플레이어는 이 이론을 알 필요가 없다.** UI/게임 내에 이론 용어가 노출되는 것은 금지된다 (제한 R4).

## 2.1 축 1 — 토도로프의 이중 서사 구조

토도로프는 추리소설에 두 개의 이야기가 공존한다고 했다.

**범죄의 이야기(S₁)**: 과거에 실제로 일어난 것. 텍스트에 직접 현전하지 않으며, 매개된 흔적을 통해서만 접근 가능하다.

**수사의 이야기(S₂)**: 현재 진행되는 것. 플레이어가 실제로 체험하는 것.

**이 게임의 존재 이유**: S₁과 S₂ 사이의 간극을 매번 다르게 열어 보이는 것.

## 2.2 축 2 — Caves of Qud의 절차적 생성 원리

### 원리 A: 고정 골격 + 가변 조직의 직조

이 게임에서: **탐정의 방법론(조사→탐문→고발)은 고정이고, 사건·인물·증거·트릭은 매번 다르다.**

### 원리 B: 사후 합리화 (Ex Post Facto Rationalization)

이 게임에서: **먼저 오판 곡선을 설계하고, 그 오판이 작동하려면 어떤 범행이어야 하는지를 역산한다.**

### 원리 C: 의미망의 조밀성

이 게임에서 조밀성은 **증거 간 연결성**이다.

### 원리 D: 치환 문법에 의한 작가적 목소리의 보존

증언과 묘사 텍스트는 템플릿 + 변수 삽입으로 생성하되, **감각 밀도와 톤이 수작업 텍스트와 일관되어야 한다.**

### 원리 E: 물의 의식 = 다기능 허브

이 게임에서 **탐문**이 그 역할을 한다 — 정보 획득, 모순 탐지, 신뢰 구축, 관계 구축이 하나의 인터랙션으로 통합.

### 원리 F: 퍼마데스 = 서사 장치

이 게임에서 **고발의 비가역성**이 그 역할을 한다.

### 원리 G: 텍스트 = 감각 인터페이스

이 게임에서: **증언의 언어가 거짓말의 힌트**이다. 묘사 텍스트의 감각 디테일이 단서이다.

## 2.3 축 3 — case_generator 스킬의 핵심 원리

### 오판 곡선이 범행보다 먼저

케이스 설계의 출발점은 "누가 범인인가?"가 아니라 **"플레이어가 어떻게 틀리는가?"**이다.

### 7배치 유형 (α~η)

| 유형 | 오판 곡선 | 핵심 | MVP |
|------|----------|------|-----|
| α 고전 분리 | 분리 폭로: 미끼 ≠ 진범 | 가장 기본적인 "아, 그 사람이 아니었구나" | **MVP 구현** |
| β 단독 범행 | 허위 분리: 분리 자체가 거짓 | 규칙 붕괴의 쾌감 | 확장 |
| γ 공모 | 과잉 정합: 두 사람의 증언이 너무 맞음 | 심문 강조 | 확장 |
| δ 연쇄 은폐 | 수렴 봉합: 시스템이 프레이밍 | 제도 저항 | 확장 |
| ε 피해자 공범 | 역전 동정: 피해자가 공범 | 윤리 충격 | 확장 |
| ζ 목격자 연쇄 | 정직한 미궁: 모두 정직하나 모두 다름 | 증언 판별 | 확장 |
| η 부재자 | 유령 추적: 범인이 현장에 없음 | 탐색 극대화 | 확장 |

## 2.4 축의 교차: Qud × 토도로프 × case_generator

| Qud 원리 | 토도로프 대응 | case_generator 대응 | 이 게임에서 |
|---|---|---|---|
| 고정 골격+가변 조직 | S₁(고정)+S₂(가변) | α형 구조(고정)+내용(가변) | 코어 루프 고정+케이스 변동 |
| 사후 합리화 | S₁이 S₂에 의해 사후 재구성 | 오판 곡선→범행 역산 | 생성 파이프라인 Step 1 |
| 의미망의 조밀성 | 흔적의 매개성 | 증거 그래프 연결성 | 2해석+교차 검증 |
| 물의 의식 | — | — | 탐문 시스템 |
| 퍼마데스 | S₁의 불변성 | S₁ 수정 금지 | 고발의 비가역성 |
| 텍스트=인터페이스 | 흔적=서사 | 감각 묘사=단서 | 증언의 언어=거짓말 힌트 |

# 제3장. 코어 루프: 5스텝 구조

## 3.1 전체 흐름

```
[1. 발견]     사건 현장 도착. 시체 확인. (연출 시퀀스)
     │
     ▼
[2. 조사 1차]  현장 탐색. 물리적 증거 2~3개 발견.
     │         각 증거는 2가지 해석을 허용.
     ▼
[3. 탐문 1차]  용의자 2~3명과 대화. 증언 수집.
     │         모순 포착 기회 (발견 증거 기반).
     ▼
[4. 조사 2차]  증언에서 파생된 추가 조사.
     │         붕괴 증거 발견 가능.
     ▼
[5. 탐문 2차]  모순 추궁. 핵심 짚기.
     │         오판 곡선 붕괴 체험.
     ▼
[6. 고발]     범인 지목 + 근거 증거 2~3개 선택.
     │         비가역적 결단.
     ▼
[7. 결과]     정답: 사건 전모 + 증거 재해석.
              오답: 부분 피드백 + 새 시각 제공.
```

## 3.2 두 가지 행위 모드

**조사한다(Investigate)** — 장소와 물건을 살펴본다. 물리적 증거를 발견한다.
**탐문한다(Question)** — 용의자와 대화한다. 증언을 얻고, 모순을 포착한다.

이 두 동사가 교대하면서 게임이 진행된다. **조사에서 발견한 것이 탐문의 질문을 만들고, 탐문에서 얻은 정보가 다음 조사의 방향을 정한다.**

## 3.3 목표 플레이 시간: 15~20분

```
발견 + 조사 1차:  5분
탐문 1차:        4분
조사 2차:        3분
탐문 2차:        3분
고발 + 결과:     4분
```

## 3.4 리듬의 곡선

```
조사 1차: 느리게  — 방을 둘러보고, 텍스트를 읽고, 분위기에 젖는다.
탐문 1차: 보통   — 대화의 리듬. 정보가 쌓인다.
조사 2차: 빠르게  — 목적이 있다. "이걸 확인하러 왔다."
탐문 2차: 급가속  — 모순을 짚는다. 긴장 최고조.
고발:    정지    — 한 순간의 고요 후 결단.
```

# 제4장. 오판 곡선: 게임의 심장

## 4.1 오판 곡선의 5요소

```
① 첫 유력 용의자: 플레이어가 자연스럽게 먼저 의심하는 대상
② 지지 증거:     그 의심을 "거의 확신"으로 끌어올리는 정보 2개
③ 붕괴 증거:     첫 가설을 단번에 무너뜨리는 결정적 반증 1개
④ 상위 해석:     붕괴 후에야 보이는 구조적 통찰
⑤ 진범 특정:     재해석 후 유일하게 특정되는 진범
```

## 4.2 생성 순서: 오판이 범행보다 먼저

```
Step 1: "플레이어가 어떻게 틀리는가"를 먼저 결정
Step 2: 그 틀림이 작동하려면 어떤 범행이어야 하는지 역산
Step 3: 범행에 맞는 장소·인물·증거를 배치
```

## 4.3 검증 5문항

1. "①을 처음 의심하는 흐름이 자연스러운가?"
2. "②를 보고 진심으로 ①이 범인이라 확신하는가?"
3. "③이 한 방에 가설을 무너뜨리는가?"
4. "④가 단순 반전이 아니라 추리 습관 자체를 수정하는가?"
5. "⑤가 증거 조합으로 유일하게 특정 가능한가?"

## 4.5 오판의 가치

**플레이어가 오래 기억하는 것은 정답이 아니라 자기가 어떻게 틀렸는가**이다.

# 제5장. 증거 시스템

## 5.1 증거의 2해석 원칙 (공리 체계 Ⅳ-2a)

**모든 핵심 증거는 최소 2개의 해석을 허용한다.** 두 해석 사이의 분기는 **다른 증거와의 교차 검증에 의해서만** 해소된다.

## 5.2 증거 그래프의 연결성

모든 증거는 최소 1개의 다른 증거와 논리적으로 연결되어야 한다.

## 5.3 결정적 경로의 유일성

**결론은 하나, 경로는 여럿.**

## 5.4 단서 밀도 제한 (구현 헌장 R3)

한 라운드에서 핵심 단서 체험은 **최대 3개**.

## 5.5 증거 구조 스키마

```javascript
Evidence = {
  id, name, location, foundIn, description,
  interpretations: { a: { text, leadsTo }, b: { text, leadsTo } },
  resolvedBy: [],
  phase: 1
}
```

# 제6장. 탐문 시스템: 짚기의 손맛

## 6.1 탐문의 3단계

### 1단계: 질문 선택
증거를 많이 발견할수록 질문 선택지가 넓어진다.

### 2단계: 증언 청취 + 누출 포착

**누출의 4유형**: 시간 불일치, 공간 불일치, 지식 누출, 감정 부조화

### 3단계: 짚기(Catch)

모순 짚기 질문을 선택하면, 세 가지가 동시에 발생한다.
1. **인물 초상의 미세 변화**
2. **감각 묘사의 삽입**
3. **심화 질문의 분기**

## 6.2 질문 생성 규칙

선택지는 **항상 최대 4개**를 넘지 않는다 (제한 R1).

1. 발견 증거 기반
2. 이전 증언 기반
3. 모순 감지 기반

## 6.3 증언의 이중 구조

범인의 증언은 **사실 + 거짓**의 혼합이다. 비범인의 증언은 **사실 + 은폐(자기 비밀 관련)**이다.

# 제7장. 수첩 시스템: 정보를 쓰는 도구

## 7.1 수첩의 4구획

| 구획 | 내용 | 핵심 기능 |
|------|------|-----------|
| **증거** | 발견한 물리적 증거 목록 | 탭하면 발견 당시 상세 텍스트 재확인 |
| **증언** | 인물별 증언 요약 | 미탐문 인물은 "(아직 탐문하지 않음)" 표시 |
| **모순** | 감지된 모순 목록 | 모순 나열하되 해석하지 않음 |
| **가설** | 현재 의심 대상 (플레이어 선택) | 선택 시 관련 증거·증언 하이라이트 |

## 7.3 수첩에 쌓이지 않는 것

수첩은 **해석을 기록하지 않는다.** 해석은 플레이어의 머릿속에만 존재한다.

# 제8장. 고발 시스템: 비가역적 결단

## 8.1 고발의 구성 요소

1. **인물 선택**: 용의자 중 1명을 범인으로 지목
2. **근거 제시**: 발견한 증거 중 2~3개를 선택하여 근거로 제출
3. **비가역성**: 고발은 1회. 되돌릴 수 없음.

## 8.2 판정 로직

```
정답 조건:
  - 지목한 인물 = 진범 (culprit)
  AND
  - 제시한 증거 중 최소 2개가 진범 특정 경로(truePathEvidence)에 포함
```

## 8.3 결과 화면

**정답**: S₁이 완전한 형태로 공개. **모든 증거가 진실의 맥락에서 재해석**된다.

**오답**: 왜 틀렸는지가 **부분적으로** 드러난다. "누구의 증언이 정말 거짓인가?" — 메타 학습 장치.

# 제10장. 인물 시스템

## 10.1 용의자 수: 3~4명 (MVP에서 3명)

## 10.2 동기의 배분 규칙

- **진범의 동기는 "가장 명백한 동기"가 아니어야 한다**
- 미끼 용의자는 가장 명백한 동기를 가진다
- 비밀은 용의자당 **1개** (제한 R3)

## 10.3 인물 타임라인

각 인물의 시간대별 위치·행동·목격자를 기록한다. 범행 슬롯은 사각지대에서 발생한다.

# 제11장. 세계 규칙

## 11.1 인과적 폐쇄성

초자연적 요소는 없다.

## 11.2 공간 구조

사건 공간은 5~6개 방(node)과 통로(edge)의 그래프. 사각지대가 최소 1개 존재.

## 11.3 흔적의 물리 법칙

접촉은 흔적을 남긴다. 세척은 2차 흔적을 남긴다. "완전한 세척"은 존재하지 않는다.

# 제12장. UI/UX 설계 원칙

## 12.1 최상위 원칙: 한 화면 = 한 장소 = 한 판단

## 12.2 네 종류의 화면

| 화면 유형 | 플레이어의 질문 | 핵심 요소 |
|---|---|---|
| **장소 화면** | "여기에 무엇이 있는가?" | 삽화 + 감각 묘사 + 선택지(최대 4) |
| **인물 화면** | "이 사람은 무엇을 말하는가?" | 초상 + 증언 + 모순 알림 바 + 질문 선택지 |
| **수첩 화면** | "내가 무엇을 알고 있는가?" | 4구획(증거/증언/모순/가설) |
| **고발 화면** | "누구를 지목하는가?" | 인물 카드 + 근거 체크박스 + 비가역성 표시 |

## 12.3 장소 화면 상세

**감각 중심 텍스트**: "약 케이스가 있습니다"가 아니라 "반쯤 열린 약 케이스. 옆에 위스키 잔, 얼음이 아직 녹지 않았다."

**오브젝트 조사**: 선택지를 누르면 화면이 전환되지 않고 확장된다.

## 12.4 인물 화면 상세

**모순 알림 바(⚠)**: **관련 증거를 발견하지 않았으면 나타나지 않음**

**짚기 연출**: 모순 짚기 질문 선택 시 (1) 인물 초상 표정 변화, (2) 감각 묘사 삽입, (3) 심화 질문 활성화.

## 12.6 색상 체계

```
배경:     어두운 남색~검정 (#0a0e17)
본문:     크림~흰색 (#e8e0d4)
발견:     호박색/금색 (#d4a857)
모순:     적갈색 (#c45c4a)
성공:     올리브 (#5b8a72)
용의자:   A: 청록 (#4a9ea8), B: 자주 (#8b5ca8), C: 올리브 (#7a8a4a)
```

## 12.7 서체 체계

```
서사 묘사:   세리프 (Noto Serif KR)
대화/UI:    산세리프 (Pretendard)
시스템:     모노스페이스 (JetBrains Mono)
고발 선언:   세리프 볼드
```

## 12.9 UI 검증 기준

- 10초 안에 "지금 뭘 해야 하는지" 아는가?
- 증거를 발견하는 순간 다음 질문이 떠오르는가?
- 모순을 짚는 순간 전율이 있는가?
- 수첩을 열면 3초 안에 "뭐가 부족한지" 보이는가?
- 고발 버튼을 누르기 직전 0.5초의 긴장이 있는가?

# 제13장. 설계 공리 (Design Axioms)

**공리 1. 감각 우위**: 모든 구현은 "플레이어는 ____를 느낀다"로 먼저 증명되어야 한다.

**공리 2. 행동 환원**: 핵심 동사는 조사한다/탐문한다 둘뿐.

**공리 3. 욕망 선행**: "무엇을 포기할지 고르는" 게임.

**공리 4. 오판 가치**: 정답은 보상이고, 오판은 콘텐츠다.

**공리 5. 실패 생산**: 모든 실패는 하나의 새 실마리를 남긴다.

**공리 6. 하부 구조 은폐**: 내부적으로 10개가 필요한 시스템이라도, 플레이어는 1개처럼 느껴야 한다.

---

# 제14장. 설계 제한 (Hard Constraints)

**R1. 질문 선택지 상한**: 최대 4개.

**R2. 루프당 단서 상한**: 핵심 단서 최대 3개.

**R3. NPC 비밀 제한**: 용의자당 비밀 1개.

**R4. 이론 용어 노출 금지**: 내부 용어는 UI에 등장할 수 없다.

**R5. 시뮬레이션 선행 금지**: 플레이 리듬이 요구하는 만큼만 구현한다.

**R6. S₁ 수정 금지**: 범인은 플레이 도중 바뀌지 않는다.

**R7. 문서-빌드 역전 금지**: 문서 설명량이 실제 빌드 체감량보다 많아지는 것을 금지한다.

---

# 제15장. 구현 프로토콜

**P1. 기능 티켓의 첫 줄 규칙**: "플레이어는 ______를 느낀다."

**P2. 기능 도입 3문항**:
1. 이 기능이 없으면 특정 플레이 감각이 사라지는가?
2. 플레이어가 내부 구조를 몰라도 그 감각을 느끼는가?
3. 이 기능이 "조사한다/탐문한다" 중 하나를 강화하는가?

**P3. 빌드 우선 증명**: 문서상 아름다움은 증명으로 취급하지 않는다.

**P4. 오판 곡선 선행**: 범행 메커니즘보다 먼저 오판 곡선 5요소를 확정한다.

```
추가: 완전한 5스텝, 오판 곡선 전체 체험, 결과 화면 증거 재해석

```

## Phase δ — 절차적 생성 (5~6주)

```
추가: case-generator 완전 구현, 풀 5×5=25 조합, 자동 검증, 삽화
```

- [ ] 오판 곡선을 강화하는가, 아니면 설명만 늘리는가
- [ ] 내부 용어를 몰라도 같은 감각을 느끼는가
- [ ] 정보가 즉시 질문/비교/짚기로 이어지는가

## 이 기능은 탈락인가?

- [ ] 이 구조를 이해해야만 재밌는가 → 탈락
- [ ] 문서가 빌드보다 더 흥미로운가 → 탈락
- [ ] 세계가 풍부해지지만 루프 목표가 선명해지지 않는가 → 탈락
- [ ] 분류가 늘었는데 플레이 감각 차이는 없는가 → 탈락
